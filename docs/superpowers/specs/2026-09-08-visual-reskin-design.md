# Visual re-skin: rights-safe imagery for Leoqo

Date: 2026-09-08
Status: approved design, awaiting implementation plan

## Goal

The app plays well but looks like a text document. Reference apps use player photos and club crests, which need licences the project does not have. This re-skin adds imagery that needs no licence: nation flags, an original pitch graphic, kit-colour club cards, and letter-tile answer entry. It reuses the existing 160 questions and existing profile data. No new game mode, no coins, lives or level economy.

Rights rule: no club crest, league logo, player likeness or kit design is reproduced. Flags are public domain. Club cards use two colours, a city and a founding year, which are facts, not artwork.

## 1. Data

All content data is generated by `scripts/build-content.py`. Nothing under `src/content/` is hand-edited.

### nations.json

`src/content/nations.json`: map of country display name to ISO 3166-1 alpha-2 code. Must cover every string that appears as an option or answer in a `world`-category question, plus every player nation used in `players` questions. Historical teams map to a present-day code with a note in the generator: West Germany → `DE`, Soviet Union → `RU`, Czechoslovakia → `CZ`.

### clubs.json

`src/content/clubs.json`: map of club display name to `{ colours: [hex, hex], city: string, founded: number }`. Must cover every answer in `clubs` and `legends` questions and every club named in a player career trail. Colours are the club's primary kit colours as plain hex values.

### Question.nation

`Question` gains an optional `nation?: string` (ISO code). The generator sets it on `players` questions from the existing nation column. The app shows it only after the hint is taken or after the answer is revealed, so it never leaks the answer.

### validateBank

Two new rules in `validateBank`, each with its own error string:

- `Unknown nation in options: <id>` when a `world` question has an option not present in nations.json.
- `Missing club card: <id>` when a `clubs` or `legends` answer, or a club in a career trail, is not present in clubs.json.

`validateBank` takes the two maps as extra parameters so the test can pass fixtures.

## 2. Visual primitives

New file `src/visuals.tsx`. Pure presentational components, no state, no I/O. `App.tsx` stays the single screen file. Styles for the new components live in `src/ui.tsx` in the existing one-line-per-group format.

### Flag

Props: `code`, `name`, `size` (default 28). Renders the emoji flag for the ISO code (two regional-indicator symbols) inside a circular badge. `accessibilityLabel` is the country name. Emoji flags render natively on Android and iOS. On Windows Chromium the emoji falls back to two letters; that is acceptable for web development and no test asserts on flag appearance.

### Pitch

Props: `children`, `height`. A View with alternating dark and light green horizontal stripes, a halfway line, centre circle and two penalty boxes, all drawn with absolutely positioned Views. Children render on top. Used as the Play-tab hero background and the quiz question header. No image assets.

### ClubCard

Props: `name`, `card` (entry from clubs.json), `compact` (boolean). Full card: vertical two-colour stripes, club initials in a rounded square, name, city and founded year. Compact chip: stripes plus name, used inside career trails. Announces the club name.

### Tiles

Props: `answer`, `seed`, `onSubmit`, `disabled`. Presentation for letter-tile entry. Logic lives in `src/core/tiles.ts`:

- `makeTiles(answer, seed)` returns `{ slots, pool }`. `slots` is the normalised answer with letters blanked and spaces kept. `pool` is the answer's letters plus four decoy letters, shuffled with the existing seeded `shuffled()` so a question always shows the same pool.
- `place(state, poolIndex)` fills the next empty slot from the pool; `remove(state, slotIndex)` returns a letter to the pool. Both return new state objects.
- `assembled(state)` returns the current string, or `null` while any slot is empty.

When every slot is filled, `Tiles` calls `onSubmit(assembled)`. The submitted string goes through the existing `choose()` so matching still uses `correctAnswer()` and aliases. Every tile is a button with an accessibility label ("Letter A" / "Slot 3, empty" / "Slot 3, letter A"). A "Clear" button empties all slots.

`Tiles` replaces the free-text `TextInput` for typed questions. The timed-mode timeout still submits `__timed_out__` unchanged.

## 3. Screens

### Play tab

- The hero card is wrapped in `Pitch`; copy and the kick-off button are unchanged.
- Each mode row gains a visual at the left: World shows three small `Flag`s, Clubs shows three compact `ClubCard` chips, Players shows a generic head-and-shoulders silhouette drawn with Views, Rules shows the existing icon, Legends shows a trophy icon.
- New block "Your journey" under the mode list: one row per difficulty (Starter, Fan, Expert). Each row shows a progress bar of seen free questions at that difficulty over the total, and a star icon when `mastery()` for rounds at that difficulty is 80% or higher. Both numbers come from existing profile data; no new persistence.

### Quiz screen

- Era, question prompt and the progress kicker sit on a `Pitch` header.
- Multiple-choice options: if the option text is a key in nations.json, a `Flag` renders before the letter badge. If it is a key in clubs.json, a compact `ClubCard` renders instead.
- Career-trail prompts (those containing "→") render each club as a compact `ClubCard` chip in a wrapping row instead of plain text.
- Typed questions render `Tiles` instead of the text box.
- Taking the hint on a `players` question additionally shows the player's nation `Flag` beside the hint text.

### Reveal panel

Beside the explanation: `Flag` for a nation answer, full `ClubCard` for a club answer, nothing for other categories.

### Unchanged

Explore, My learning, Settings, shop, age gate and privacy screens are unchanged except where they already reuse the mode rows.

## 4. Testing

Unit (Vitest):

- `tests/tiles.test.ts`: pool is deterministic for a seed, contains every answer letter, has exactly four decoys; placing and removing round-trips; `assembled` is null until full; the assembled string for the correct letters matches `correctAnswer()`.
- `tests/quiz.test.ts`: new validateBank rules fire on fixtures and pass on the generated bank with the generated maps.

E2E (Playwright, static `dist/`):

- Existing twelve tests stay green.
- New: a typed question answered through tiles reaches the reveal panel with the correct feedback text.
- The existing "no external requests" test covers the flag approach because emoji need no network.

Accessibility: every new interactive element has a role and label; flags and club cards announce their names; contrast of text on the pitch header stays at 4.5:1 or better (white on the dark stripe colour).

## Out of scope

- Real crests, league logos, player photos.
- Lineup detective mode (flags in formation, type the club). Next spec.
- Coins, lives, spin wheels, level unlock economy.
- Any change to session rules in `src/core/quiz.ts` beyond the two validation rules.
